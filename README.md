# singularity_oop

В этом учебном проекте я собираю ядро интернет-магазина и разбираюсь с ООП.

## Что уже есть

- В `src/product.py` я описал товар: название, описание, цену и количество в наличии.
  Цену сделал приватной, для чтения и изменения использую свойство `price`.
  Нулевую и отрицательную цену отклоняю с предупреждением. При снижении цены
  запрашиваю подтверждение: `y` для согласия, `n` для отказа.
  Через `Product.new_product(data)` я создаю обычный товар из словаря.
  Если передать список с товаром того же названия, я складываю количество и оставляю большую цену.
- В `src/category.py` я описал категорию с названием, описанием и приватным списком товаров.
  Для добавления использую `add_product()`. Через свойство `products` получаю строки
  вида `Название, 80 руб. Остаток: 15 шт.` Счётчики `category_count` и `product_count`
  увеличиваю при создании категории и добавлении товара.
- В `src/utils.py` я добавил загрузку категорий и товаров из JSON. Пример храню в `data/products.json`.
- В `main.py` я показываю, как пользоваться классами.

## Домашняя работа 16.1

Я добавил два класса на основе `Product`:

- `Smartphone`: производительность `efficiency`, модель `model`, память `memory` и цвет `color`.
- `LawnGrass`: страна `country`, срок прорастания `germination_period` и цвет `color`.
  Срок прорастания я передаю строкой, например `"7 дней"`.

Общие поля я заполняю через `super().__init__`. Вывод товара, работу с ценой
и сложение оставил в родительском классе, чтобы не копировать код.

В `__add__` я сравниваю классы через `type()`. Два смартфона или две упаковки
травы можно сложить. Для товаров разных классов я выбрасываю `TypeError`.
Обычный `Product` тоже можно сложить только с другим `Product`.

В `Category.add_product()` я добавил проверку `isinstance()`. Метод принимает
`Product` и его наследников. Если передать другой объект, я выбрасываю `TypeError`
до изменения списка и счётчика товаров. В одной категории можно хранить разные виды товаров.

В `main.py` я показал оба новых класса, сложение и обработку ошибок.
В тестах проверил новые поля, унаследованные методы, ограничения и счётчики.

Я веду работу по GitFlow: новые задания делаю в ветках `feature/*`,
а пул-реквесты направляю в `develop`. Для этой работы создал `feature/inheritance`.
Код предыдущих заданий перенёс в неё, поскольку их пул-реквесты ещё открыты.
